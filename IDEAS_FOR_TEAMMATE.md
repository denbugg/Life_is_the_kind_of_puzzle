## 0. Задача и главный факт

24×24 сетка из 20×20 тайлов, каждый тайл независимо деградирован (яркость
±30, контраст 0.7–1.3, шум σ40–55, blur 3×3, JPEG q35–50). Метрика — mean
SSIM по 700 test.

- Вход как есть: SSIM ≈ 0.08–0.11. Идеальная сборка без реставрации:
  ≈ 0.44–0.50. Идеальная сборка + NLM-реставрация: ≈ 0.57+.
- **Лидер (0.4) ≈ полностью решил placement.** Вся соревновательная игра —
  расстановка, реставрация — вторичный бонус.

## 1. ГЛАВНАЯ ЖИВАЯ ЗАЦЕПКА: происхождение данных — теперь operational (14 test-картинок закрыты!)

Датасет — фотоархив публичных мероприятий Т-Банка/Тинькофф и Центрального
Университета (Т-Образование). Изначальная находка (2026-07-11 утро) была 2
точных train-кадра из 43 публичных фото на одной странице meetup.tbank.ru.
С тех пор это выросло в полноценный retrieval-пайплайн:

**Источники прокраулены** (`E:/pazzle_work/source_forensics/manifests/`):

| источник | фото | события |
|---|---:|---:|
| T-Bank meetups API (полный публичный архив) | 5,058 | 894 |
| Central University (сайт + sitemap) | 553 | — |
| CU events / галереи (7/11) | 176 + 335 | — |
| CU новостная лента (cu.ru/news, Tilda) | 476 | 146 постов |
| T-Education | 531 | — |

**Результат — точные совпадения кадров**:

- **Train**: 161 уникальный точный target (139 T-Bank + 22 CU/static),
  подтверждено пиксельно (mean SSIM центр-кропа к target = 0.9536).
- **Test: 14 картинок закрыты точным оригиналом** — из них 12 T-Bank, 2 CU.
  Список: `img_000013, 000275, 000313, 000697, 000809, 000840, 001990,
  001997, 002051, 002127, 002647, 002829, 002948, 002950`.

**Метод (не «похожая картинка», а геометрически проверенное совпадение)**:
неупорядоченный мешок из 576 тайлов → инвариантный к перестановке fingerprint
→ top-K похожих кандидатов среди всех прокрауленных фото → для каждого
кандидата решается 10×10 (даунсемпл) глобальное соответствие тайл↔клетка
кандидата (`assignment_mean_correlation`) → жёсткий geometric gate: **≥5
SIFT-совпадений с одинаковыми координатами между реконструированным грязным
изображением и кандидатом + identity_fraction ≥ 0.35 + RANSAC-гомография**.
Это отсекает «визуально похоже, но другое фото» — на test rank-2 кандидат
(второй по similarity) верифицируется **0 раз из 688** попыток, т.е. метод
не подгоняет шум, а действительно находит точные копии.

Визуально проверено вручную (я лично сверил 3 пары input↔найденный
оригинал) — совпадения бесспорные: жёлтый бейджик «T» на ёлочном шаре
виден в шумном инпуте на той же позиции, что на чистом фото; блики
концертного света; жёлтый бейдж на футболке участника — всё совпадает
пиксель-в-пиксель по расположению.

## 3. Закрыто с числами — НЕ ПОВТОРЯТЬ

Локальный сигнал шва после пофрагментной деградации НЕ достаточен для
глобальной сборки. Пять независимых постановок упёрлись в один потолок:

| ветка | лучший результат | вердикт |
|---|---|---|
| Классический MGC/градиенты | bb_prec ≈ 0.05 | мертво |
| CNN PairwiseNet (+hard neg, +ensemble) | bb_prec ≈ 0.41–0.53 | мертво |
| DirectPoseNet U/D/L/R + non-direct | recip precision 0.46 | мертво |
| 48-way смещения | коллапс в far | мертво |
| **Listwise seam ranker** (candidate-matched, 163k и 646k параметров) | p=0.745 @ cov 0.092; p=0.954 @ cov 0.042; сборка: neighbour 0.008 | закрыт 2026-07-10 |

Также закрыты: прямой canvas-генератор (усреднённая сцена), абсолютные
координаты/Sinkhorn (chance 0.003 — ill-posed между сценами), row/column
декомпозиция, 2×2 плакетки (AUC 0.815 на synthetic, но проигрывает на
реальных кандидатах; C4 coverage в candidate-пуле всего 1.9%),
denoise-перед-matching (L1 лучше, ранжирование то же), triple-context A–B→C
(R@1 0.172 < 0.27 у пары), **dense pointer по всему мешку** (R@1=0 после
починки AMP), Gromov/manifold (корреляция графовых расстояний с геометрией
~0.18), утечки/retrieval train↔test (нет), позиционные следы в
деградации (нет).

Оракульный факт, дающий надежду иерархике: если тайлы правильно разбиты на
группы по 16, существующий скорер собирает каждый 4×4 блок с placement 0.68.
Т.е. узкое место — group assignment, не локальная сборка внутри группы.

## 4. Живые направления (кроме retrieval)

1. **Гибрид: seed-компоненты + контекстный рост.** Стартовать с p≈0.95
   seeds, расширять компоненты, скоря присоединение тайла к уже собранному
   2×2/3×3 контексту (не к одиночному тайлу!). Оракул triple по НОИЗНЫМ
   тайлам провалился, но контекст побольше + счёт против собранного канвы —
   не проверен.
2. **Latent prior / per-puzzle оптимизация** (недоделано у Codex-агента):
   VAE на чистых 96×96 сценах + оптимизация latent-кода под мешок через
   Sinkhorn. Обучение прервано; oracle-критерий сформулирован (кодировка
   истинной карты должна восстанавливать позиции) — начать с него.
3. **Generative continuation** (недоделано): предсказывать ЧИСТЫЙ следующий
   тайл из контекста + retrieval noisy-тайлов отдельным энкодером. Уперся в
   runtime, не в качество — после фиксов инфраструктуры (см. §5) может
   получить честный гейт.
4. **Макро-уровень**: обучаемое разбиение мешка на регионы (partition),
   потом иерархическая сборка. Слабо исследовано.

## 5. Инфраструктурные грабли (сэкономят вам часы)

1. **8 GB VRAM + WDDM**: если шаг держит >7 GB активаций, PyTorch тихо
   уходит в подкачку общей памяти — шаг замедляется в 10–25×. Лечение:
   gradient checkpointing по чанкам (см. `score_candidate_rows(...,
   checkpoint_chunks=True)`), питать модель чанками фиксированного размера.
2. **`cudnn.benchmark=True` + переменные формы батча** = многосекундный
   ре-автотюн КАЖДЫЙ шаг. Паддить хвостовой чанк до константного размера.
3. **AMP/GradScaler может тихо пропускать optimizer-шаги** при non-finite
   градиентах — dense pointer «не учился» именно из-за этого. Логируйте
   факт применения апдейта.
4. `np.load` для .npz ленивый — материализуйте массивы, иначе MemoryError в
   даталоадер-воркерах.
5. Обучение на synthetic (distort.py воспроизводит деградацию до ~0.01 SSIM,
   метки точные); recover-кэш на real данных содержит ~12% шума меток — для
   обучения не использовать, только для eval.
6. Валидация ТОЛЬКО на свежих exact-synthetic held-out (последние 300 имён
   train). Все прошлые «красивые» промежуточные метрики умирали именно на
   честном гейте.

## 6. Минимальный протокол проверки любой новой идеи (no-gamble)

1. Сначала oracle-gate (идеальные входы → работает ли механика вообще).
2. Потом короткий обучающий gate (сотни шагов) на exact-synthetic held-out.
3. Продолжать только при кратном (не процентном) превосходстве над текущим
   потолком: reciprocal precision ≥ 0.75 при coverage ≥ 0.2, или
   neighbour accuracy ≥ 0.25 после сборки.
4. Отрицательный результат фиксировать с числами и закрывать ветку.
